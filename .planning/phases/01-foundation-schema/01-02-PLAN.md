# Plan: 01-02 - Define and migrate Prisma schema

## Objective
Define the Form and Submission models in Prisma and migrate the database.

## Context
After the app is initialized, we need to customize the `prisma/schema.prisma` file to support our form builder data needs.

## Requirements
- **FND-02**: Set up Prisma schema for Forms and Submissions.

## Threat Model
- **Threat**: SQL Injection via dynamic field names.
- **Mitigation**: Using Prisma with JSON fields abstracts the raw SQL, but we should ensure the `schema` JSON is validated before saving.

## Tasks

<task wave="1">
  <action>
    Modify `prisma/schema.prisma` to add the `Form` and `Submission` models as researched.
    Add:
    ```prisma
    model Form {
      id        String   @id @default(uuid())
      shop      String
      title     String
      handle    String   @unique
      schema    Json
      settings  Json
      createdAt DateTime @default(now())
      updatedAt DateTime @updatedAt
    }

    model Submission {
      id        String   @id @default(uuid())
      formId    String
      data      Json
      createdAt DateTime @default(now())
    }
    ```
  </action>
  <read_first>
    - prisma/schema.prisma
  </read_first>
  <acceptance_criteria>
    - `prisma/schema.prisma` contains the new models.
  </acceptance_criteria>
</task>

<task wave="2" autonomous="false">
  <action>
    Run the Prisma migration to update the local SQLite database.
    Command: `npx prisma migrate dev --name init_forms`
    Note: This may require user interaction for the migration name if not passed.
  </action>
  <read_first>
    - prisma/schema.prisma
  </read_first>
  <acceptance_criteria>
    - `npx prisma migrate status` shows all migrations applied.
    - `prisma/migrations/` contains the new migration.
  </acceptance_criteria>
</task>

<task wave="3">
  <action>

  </action>
  <read_first>
    - prisma/schema.prisma
  </read_first>
  <acceptance_criteria>
    - Command completes successfully.
  </acceptance_criteria>
</task>
